# parity-mesh — побитовое сравнение мешера C# с JS-оригиналом

Проверяет, что `Assets/VoxelForge/Scripts/Mesh/MeshCore.cs` (`MeshCore.run`) выдаёт **ровно те же** вершины и индексы,
что и `createSharedMeshCore().run()` из эталонного `pretty.js` (код mesh-воркера), на одних и тех же заданиях.

## Запуск

```sh
sh Tools/parity-mesh/run.sh <путь/к/pretty.js> [outDir] [--quick] [--only=<подстрока имени задания>]
```

* `outDir` по умолчанию — `$TMPDIR/vf-parity-mesh` (или `/tmp/vf-parity-mesh`).
* `--quick` — один сид вместо четырёх (≈10 с), без флага — полный набор (≈30 с, 71 задание, ~2.1 млн вершин).
* Код выхода 0 и строка `outputs: N/N jobs bit-identical` — паритет есть; иначе печатается первая разница по каждому
  заданию (бакет, номер вершины, декодированные поля JS и C#). `node compare.js <outDir> --all` — все различия.

Нужны `node` (22+), `mcs` и `mono`.

## Что делает

1. `jsenv.js` загружает `pretty.js` в node: подставляет данные `/*EXTRACTED ...*/` из `Resources/VoxelForge`,
   все браузерные API заменяет «пустой» заглушкой и исполняет верхний уровень до таблиц блоков. Получаем настоящие
   `B`, `blocks`, `VIRTUAL_BLOCKS`, `createSharedMeshCore`, `createWorldGenKernel`, `GEN_WORKER_SOURCE`, а
   `workerBlockCfg` строится так же, как в `initWorkerEngine()`.
2. `gen-jobs.js` готовит задания и прогоняет JS-мешер (один экземпляр ядра на все задания, как в воркере):
   * **реальные чанки**: настоящий gen-воркер (`GEN_WORKER_SOURCE`: генерация, смешение жидкостей, освещение,
     упаковка секций, метаданные) для 4 сидов — чанки у начала координат и центры структур
     (пирамида, аванпост, портал, корабль) + 4 соседа; полезная нагрузка собирается как в
     `meshSectionPayload`/`meshMeta`/`ingestGeneratedMeta`; полные и частичные задания;
   * **синтетика**: плотный случайный микс всех id и виртуальных блоков со случайной метой и светом, края мира
     (секции 0/1/22/23), жидкости (все уровни воды/лавы, падающая вода, водоросли, waterlogged), формы
     (ступени, заборы/стены/панели/калитки, рельсы, сундуки), решётка «каждый id × несколько мет» и «каждый
     виртуальный ключ», кластеры одинаковых виртуальных блоков через границу чанка, ровный океан (слияние
     плоских верхов воды), сетки всех масок соседей для рельсов/соединений/углов ступеней, все варианты `potKey`,
     «странные» типы значений меты (`""`, числа, строки-числа, `true`), сломанная нагрузка (секции без света,
     дубликаты секций, dx/dz/si вне диапазона, мета вне окна 48×48), пустые и вне-диапазонные `sis`,
     частичные задания с неотсортированными и повторяющимися `sis`.
3. `MeshParity.cs` собирается `mcs` вместе со всеми скриптами проекта и копией `UnityStubs.cs`, в которой
   `Resources.Load<TextAsset>` читает файлы из `Resources/` (оригинальные заглушки не меняются). Он вызывает настоящие
   `InitData` → `InitBlocks` → `buildMesherConfig`, гоняет `MeshCore.run` по тем же заданиям в том же порядке
   и дополнительно проверяет, что `aggO/C/W/T` — это точная конкатенация `full24`.
4. `compare.js` сравнивает конфиг мешера (`cfg_js.json` и `cfg_cs.json`, по смыслу: `null`/`undefined` ≡ `-1`)
   и выходные файлы побайтно.

## Формат дампа (`js/*.bin`, `cs/*.bin`, uint32 LE)

`magic 0x4d564631, full, nSis, sis[], agg` и далее либо (agg=1, полное задание) 4 бакета opaque/cutout/water/transparent
агрегата + `secLens[24][8]`, либо (agg=0) `nParts` и для каждой части `si` + 4 бакета. Бакет: `nV, nI`, затем на
вершину 8 слов — биты f32 `x, y, z`, half `u`, half `v` (как `f32ToHalf` в `packTerrainVerts`), `tile` (ToUint16),
биты f32 `shadeAlpha`, `light` (ToUint8); затем индексы. То есть сравнивается именно то, что попадает в GPU-буфер.

## Покрытие JS-мешера

```sh
NODE_V8_COVERAGE=<outDir>/cov JSENV_DUMP=<outDir>/jsenv.json node Tools/parity-mesh/gen-jobs.js <pretty.js> <outDir>
node Tools/parity-mesh/cover.js <outDir>
```

Печатает строки `createSharedMeshCore`, которые ни разу не выполнились. Сейчас это только мёртвый код
(`waterVisLevelAt`, `emitWaterQuad`, `workerConnects`, `stopsLight`, `attenuation`, ветки виртуальных форм, которых нет
в `virtual_blocks.json`) и `??`-запасные значения для полей, которые в данных всегда заданы.
