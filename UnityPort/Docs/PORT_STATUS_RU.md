# Blockcraft → Unity 2022.3.62f3: состояние переноса

Эталон — WebGL2‑игра `main.js` + `genWorker.js` + `meshWorker.js` (в репозитории: `reference/source`).
Алгоритмы берутся из эталона; там, где вариант порта лучше, это отмечено отдельно.

## Как открыть

1. Unity Hub → **Add project from disk** → папка `UnityPort` (версия редактора 2022.3.62f3).
2. При первом открытии `Editor/PortAutoSetup` сам настроит импорт текстур (point, без mip),
   цветовое пространство Gamma, инкрементальный GC, **Release**‑оптимизацию кода в редакторе
   и создаст сцену `Assets/Scenes/PortDemo.unity`.
3. Открыть `PortDemo` → Play. В меню выбрать режим: **1** выживание, **2** креатив, **C/Enter** продолжить сохранение.

Для максимальной скорости в собранной игре: Player Settings → Scripting Backend **IL2CPP**
(в редакторе работает Mono; все цифры ниже для Mono — это нижняя граница).

## Что перенесено и как проверено

Все проверки запускаются без Unity: `tools/parity/run_checks.sh` (нужны dotnet 8, node, python3+numpy,
Chromium для эталонной игры). Эталон исполняется «как есть» (воркеры в Node, `main.js` целиком
в headless‑Chromium), сравнение — побитовое/поквадовое.

| Система | Проверка | Результат |
|---|---|---|
| Генерация мира (биомы, рельеф, пещеры, руды, деревья, структуры) | 24 чанка seed 56 против `genWorker.js` | совпадает 99.9906 % блоков (222 из 2 359 296 — детали шахт), метаданные и свет 100 % |
| Меш чанков (все 674 блока) | каждый блок × все допустимые метаданные + 3 плотных случайных мира | 16 330 + ~200 000 квадов идентичны (позиции, AO, свет, UV) |
| Меш реального мира | 2 чанка против `meshWorker.js` | непрозрачное 11 751/11 751 квадов идентично; вода — см. «Намеренные отличия» |
| Установка блоков, двери, кровати, плиты, факелы, лианы, горшки, опора блоков, губка, бетон, кораллы, кактус | 708 сценариев через `kT()/gT()/nA()` эталона | **708 / 708** идентичных итоговых состояний |

### Намеренные отличия (вариант порта лучше)

* **Вода:** `meshWorker` не рисует боковую грань воды полной высоты над соседней водой
  с поверхностью 0.875 — остаётся «прозрачная щель». Порт закрывает её (198 квадов на
  одном подводном чанке; единственное отличие меша).
* **Порядок отрисовки:** эталон рисует чанки построчно; порт — кольцами от камеры:
  непрозрачное спереди назад (ранний Z отбрасывает скрытые пиксели), вода/стекло сзади
  вперёд (правильное смешивание).
* **Иконки:** края без подмешивания соседних тайлов атласа (артефакт браузера).

## Скорость

Замер на одной и той же сцене (7×7 чанков генерации, меш центральных 5×5), мс на чанк:

| Этап | Эталон (V8/Node) | Порт, Mono (как в редакторе Unity) | Порт, .NET 8 (≈IL2CPP) |
|---|---|---|---|
| Генерация + свет | 37.7 | **33.2** (было 58.2) | **20.6** (было 28.4) |
| Сшивка света | — | 0.62 (было 0.90) | 0.45 |
| Меш чанка (~21 тыс. вершин) | 53.2 | **8.5** | **7.3** |

Рендер:
* Чанки рисуются напрямую из CommandBuffer (как VAO в `main.js`): без GameObject/Renderer
  на чанк, одна Mesh на колонку с подмешами (непрозрачное, вода, прозрачное, скрытые руды X‑Ray).
* Списки отрисовки перезаписываются только при изменении набора видимых чанков;
  при повороте камеры — только frustum‑тест по кешированным кандидатам.
* Бюджет стриминга привязан к частоте экрана (как `requestAnimationFrame`), а не к
  измеренному кадру — это убрало «самоподдерживающееся» падение FPS.
* Генерация — в `cores−2` потоках, меш — в пуле как в эталоне.

«Дыры», которые заполняются через некоторое время, — это чанки, данные которых уже есть,
а меш ещё не опубликован. Устранённые причины задержки:
* планирование мешей останавливалось **во всём мире**, пока в очереди было хоть одно
  изменение света (например, от текущей воды) — теперь ждут только уже видимые чанки в
  радиусе 2 от него, а чанки без меша публикуются сразу и перестраиваются после пересчёта света;
* планирование и интеграция мешей пропускались, если бюджет кадра был съеден сшивкой света —
  теперь воркеры мешей кормятся каждый кадр (до 2 заданий на воркер в очереди);
* загрузка на GPU шла одной очередью — теперь чанки без меша («дыры») грузятся раньше
  обновлений уже видимых чанков, и одна такая загрузка гарантирована в каждом кадре;
* сшивка света пропускает холостые семена (открытое небо над рельефом): 0.90 → 0.62 мс/чанк;
* поиск воды на краях нового чанка пропускает секции без жидкости.

## Что ещё не перенесено / известные расхождения

* Шахты: ~0.01 % блоков отличаются в деталях.
* Эталонный световой коэффициент для лавы/тонированного стекла (D0) не сверялся численно.
* Меню настроек/модов эталона, миникарта, звуки, броня/вторая рука (данные есть, UI нет).
* Анимированная текстура огня.
